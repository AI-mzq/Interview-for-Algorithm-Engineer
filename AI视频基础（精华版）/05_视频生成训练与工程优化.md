<h1 id="4.5.1_视频训练数据处理：样本构建、文本描述与数据供给">4.5.1 视频训练数据处理：样本构建、文本描述与数据供给</h1>

> 本节讨论视频训练数据如何构建并送入模型：切片、镜头切分和去重决定训练样本及其分布，文本描述提供与片段对应的内容条件，读取、解码和预处理则影响数据供给速度。训练规格与分桶设计见4.5.2，计算、通信和负载等整体训练效率问题见4.5.5。

<h2 id="4.5.1.1_面试问题：视频训练的数据供给容易在哪些环节出现瓶颈？如何定位？">4.5.1.1 面试问题：视频训练的数据供给容易在哪些环节出现瓶颈？如何定位？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

视频训练的数据供给瓶颈可能出现在读取解码、预处理与潜变量编码、批次组装等环节，需要结合阶段计时判断：

1. **读取与解码。** 远端存储带宽不足、随机 seek、编码格式混杂、损坏文件重试，都会让 CPU 侧供给出现长尾。此时最典型的现象不是报错，而是训练进程间歇性等数据。
2. **预处理与 latent 编码。** resize、裁剪和 VAE 编码若在线执行，会占用 CPU/GPU 时间；预先缓存 latent 能减轻训练时计算，却会增加存储成本，并要求 VAE 版本、归一化和数据增强策略保持一致。
3. **组 batch。** 不同帧数、分辨率和长宽比造成的 worker 负载不均与尾部等待，也会打断稳定供给。这里先关注“能否持续形成 batch”，token 利用率和 bucket 设计放到 4.5.2 再讨论。

如图 5-1 所示，排查时应给每个阶段单独记录处理耗时、队列深度、失败率和输出速率，而不是只看 GPU 利用率。

定位瓶颈时，可以做一组由简到全的替换实验：

- 用随机张量替代真实数据，先确认训练计算和通信本身的上限；
- 换成预计算 latent，判断问题是否集中在读取、解码或 VAE；
- 再依次恢复在线 VAE、视频解码和完整过滤链路，观察 samples/s、有效 tokens/s、data wait time 与 GPU 空闲时间在哪一步明显恶化。

这里有一个常见误区：**GPU 利用率低不等于数据管线一定慢**，小算子、同步通信同样可能造成空闲。只有结合阶段计时和替换实验，才能把“GPU 在等什么”定位清楚。

> **面试速答**：视频数据供给主要会卡在读取解码、预处理与 VAE 编码、批次组装等环节。排查不能只看 GPU 利用率，应记录各阶段耗时和队列，再用“随机张量 → 缓存 latent → 在线 VAE → 完整视频链路”的替换实验逐层恢复，定位吞吐下降从哪一步开始。

参考资料：[Stable Video Diffusion](https://arxiv.org/abs/2311.15127)、[CogVideoX](https://arxiv.org/abs/2408.06072)

<h2 id="4.5.1.2_面试问题：视频切片、镜头切分与去重如何影响训练数据和生成效果？">4.5.1.2 面试问题：视频切片、镜头切分与去重如何影响训练数据和生成效果？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

切片定义了模型看到的基本时间单元，去重则改变了每类内容在训练中的实际权重。二者处理不当，即使原始视频规模很大，有效数据分布也可能已经失真。

**第一，clip 边界要符合目标任务。** 对单镜头连续生成，clip 通常应落在同一 shot 内，并尽量保留完整动作。若没有切镜条件，却把无关镜头拼进同一 clip，模型看到的只是一次无法解释的时空跳变。多镜头生成或视频编辑可以使用跨镜头样本，但切换位置和语义应被显式建模，不能与连续运动样本混在一起处理。

**第二，采样策略要控制时间分布。** 帧率、真实时长、动作是否完整以及运动强弱都会改变监督信号。大量静止 clip 会让数据分布偏向低运动，但静止样本并非都该删除：若目标产品包含静态镜头，就应保留合理比例。关键是统计并控制分布，而不是套用统一阈值。

**第三，去重要看“有效重复”，不只是文件是否相同。** 同一素材可能经过裁剪、转码、加字幕或变速后再次出现。只做文件哈希只能发现完全重复，还需结合感知特征或 clip 表征识别近重复，并按来源或模板做聚类。近重复不只是增加过拟合风险，还会悄悄放大某些主体、风格和动作的采样权重；训练集与验证集之间也要单独检查重复，避免评测偏高。

工程上应同时检查切分准确率与处理后的分布：抽样复核镜头边界的误切和漏切，统计重复簇大小、时长、帧率和运动强度，并在固定验证集上比较清洗前后的结果。这样才能判断过滤规则是在去噪，还是误删了业务需要的长尾样本。

> **面试速答**：切片决定模型学习什么样的时间变化，去重决定不同内容在训练中的实际权重。单镜头任务通常要求 clip 不跨无关切镜并尽量覆盖完整动作；采样还要控制时长、帧率和运动分布。去重则要从完全重复扩展到转码、裁剪和模板化近重复，同时防止训练集与验证集交叉污染。

参考资料：[Stable Video Diffusion](https://arxiv.org/abs/2311.15127)、[CogVideoX](https://arxiv.org/abs/2408.06072)

<h2 id="4.5.1.3_面试问题：用于文生视频训练的文本描述应包含哪些信息？如何保证与视频片段一致？">4.5.1.3 面试问题：用于文生视频训练的文本描述应包含哪些信息？如何保证与视频片段一致？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

视频文本描述（video caption）为文生视频训练提供文本条件，应准确描述对应片段中的主体、动作和时间关系。原视频经过切片后，需要重新核对描述的时间范围，不能直接沿用包含片段外事件的整段描述。

一条有效 caption 通常包含四类信息：

1. **主体与场景**：谁在什么环境中，关键属性和主体关系是什么；
2. **动作与变化**：谁做了什么，运动方向、速度或状态如何变化；
3. **时间关系**：动作是同时发生还是先后发生，事件是否分阶段推进；
4. **镜头信息**：景别、视角和相机运动，但只描述画面中能够判断的内容。

真正难的是动态信息。只根据少量关键帧生成 caption，往往能看见“有什么”，却看不准“怎么动”和“先后发生了什么”。因此工程上常把帧级视觉证据、整段视频表征、镜头边界和已有元数据合并，再生成或重写训练 caption。不同粒度的描述可以并存，但都要落回视频证据，不能为了丰富而补写不存在的动作或镜头语言。

caption 质量主要看三点：

- **事实一致**：主体、数量、属性、动作与视频相符，不能把模型猜测当成事实；
- **时间可辨**：描述能区分方向、动作阶段和先后关系，而不只是静态名词堆叠；
- **训练可用**：重要信息位于文本编码器可见范围内，表达粒度与推理时的用户 prompt 不至于严重错位。

评估时不能只用 caption 长度或单一图文相似度。更可靠的做法是构造方向、顺序、主体—动作绑定和相机运动等对照样本，检查模型能否区分近义但时序关系不同的 prompt；同时抽样做人审，尤其关注 caption 模型容易产生的动作补写和主体错配。若自动评估器与 caption 生成器同源，还要警惕二者共享错误偏好。

> **面试速答**：高质量 video caption 要基于整段视频证据，准确描述主体、动作、时间顺序和可判断的镜头变化。重点不是越长越好，而是事实正确、动态关系清楚、训练时可被文本编码器有效利用；评估时应专门测试方向、先后顺序和主体—动作绑定，不能只看图文相似度。

参考资料：[Stable Video Diffusion](https://arxiv.org/abs/2311.15127)、[CogVideoX](https://arxiv.org/abs/2408.06072)

<h1 id="4.5.2_视频训练规格与资源约束：帧数、分辨率、token预算与分桶">4.5.2 视频训练规格与资源约束：帧数、分辨率、token预算与分桶</h1>

> 本节讨论如何在计算与显存约束下安排视频训练规格。对于将时空潜变量划分为token的Transformer主干，帧数、分辨率、VAE压缩率和patch大小共同决定视频序列长度；分桶（bucketing）则将形状相近的样本组织成批次。训练时既要评估单样本与批次的资源开销，也要控制不同规格的采样比例。

<h2 id="4.5.2.1_面试问题：如何估算视频训练的token数量？它如何影响计算与显存开销？">4.5.2.1 面试问题：如何估算视频训练的token数量？它如何影响计算与显存开销？</h2>

**难度评分：⭐⭐⭐⭐⭐ (5/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

token预算用于限制单样本或单个批次处理的token规模，需要分别明确单样本序列长度与批次总token数。以下以将Video VAE潜变量划分为patch token的DiT为例估算，其他架构需按实际表示方式计算。假设输入视频大小为 $T \times H \times W$，Video VAE 在时间和空间上的下采样率为 $r_t,r_h,r_w$，DiT 的 patch 大小为 $p_t,p_h,p_w$。忽略边界补齐且各维可以整除时，单条视频的 token 数为：

```math
N_{\mathrm{vid}}
=\frac{T}{r_t p_t}
\times\frac{H}{r_h p_h}
\times\frac{W}{r_w p_w}
```

这条式子也划清了一个容易混淆的边界： $T_l \times H_l \times W_l$ 是 VAE 的 latent 网格，其中 $T_l=T/r_t$、$H_l=H/r_h$、$W_l=W/r_w$；经过 patchify 后才是 DiT 的视频 token。文本或其他条件是否增加同一条序列的长度，取决于注入方式：拼接后做联合 attention 会增加序列长度，单独做 cross-attention 则形成另一部分计算。

**序列长度直接改变算力和显存。** 对稠密全局 self-attention，注意力部分随序列长度二次增长；逐 token 的投影和 MLP 等计算则近似线性增长：

```math
C_{\mathrm{attn}}\propto B N_{\mathrm{vid}}^2,
\qquad
C_{\mathrm{token}}\propto B N_{\mathrm{vid}}
```

其中 $B$ 是 batch size，上式假设批次内视频token数相同，且模型宽度、层数等配置固定。局部、分解或稀疏注意力会改变二次项，具体成本还受隐藏维度、激活重计算、并行方式和算子实现影响。因此 token 数适合作为第一层预算，不能代替真实性能测量。

**它还会改变训练权重。** 如果 loss 对 batch 内所有 token 直接求平均，长视频和高分辨率样本贡献的元素更多；如果先按样本归一化再求平均，各规格样本的权重又不同。混合规格训练必须明确归一化口径，否则数据采样比例相同，实际优化权重也可能不同。

工程上应同时记录单样本最大 token 数、batch 总 token 数、峰值显存、step time 和有效 tokens/s。只固定 batch 总 token 仍不一定能固定计算量：对稠密注意力，少量长序列可能比大量短序列更贵。最终应按不同规格实测，再决定 batch size、梯度累积和并行策略。

> **面试速答**：对于采用潜变量patch token的主干，可根据帧数、分辨率、VAE下采样率和patch大小估算单样本token数，再统计批次总token数。token规模影响显存、注意力计算和batch size，损失归一化方式还会影响不同规格样本的训练权重。排查时既要看单样本与 batch 总 token，也要看实测峰值显存和 step time，因为相同总 token 在不同序列长度下未必具有相同成本。

参考资料：[Attention Is All You Need](https://arxiv.org/abs/1706.03762)、[CogVideoX](https://arxiv.org/abs/2408.06072)

<h2 id="4.5.2.2_面试问题：如何评估Video-VAE是否适合下游视频生成训练？">4.5.2.2 面试问题：如何评估Video VAE是否适合下游视频生成训练？</h2>

**难度评分：⭐⭐⭐⭐⭐ (5/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

评估Video VAE是否适合下游训练，需要同时检查重建质量、下游生成效果和端到端成本。压缩更强可以减少生成主干处理的序列规模，但不能仅凭压缩倍数或重建指标判断是否值得采用。

**1、重建质量是否满足目标任务**

在相同输入视频上检查小物体、文字、手部、人物身份、快速运动及首尾帧，结合重建指标与失败样本判断。应按内容类型分别检查，避免整体平均分掩盖特定细节或动作的损失。

空间压缩、时间压缩与潜变量通道数的原理和取舍见 [4.2.2.3](02_AI视频生成核心架构.md#4.2.2.3_面试问题：Video-VAE-的空间压缩、时间压缩和潜变量通道数应如何权衡？)。这里重点判断候选VAE能否保留任务需要的信息。

**2、潜变量是否适合生成主干学习**

使用相同训练数据、可比的生成主干配置和明确的训练预算，分别在候选VAE的潜变量上训练，比较收敛速度、生成质量与时序稳定性。更换VAE时，需要重新训练或适配生成主干，不能直接替换后用旧主干的输出判断优劣。

重建质量更好，只说明真实视频经过编码、解码后保留得更好，不能保证生成主干在相同预算下也能学好对应的潜变量分布。

**3、端到端成本是否合算**

记录VAE编码与解码吞吐、峰值显存、潜变量缓存体积，以及生成主干的训练和推理耗时。缓存体积还受潜变量通道数与数值精度影响，不能只根据时空网格的缩小倍数推算。

选型时先排除无法满足任务质量要求的候选，再比较其下游生成表现与整体成本，避免主干节省的开销被更昂贵的VAE编码、解码抵消。

> **面试速答**：先用真实视频重建检查细节与运动信息是否保留，再训练或适配生成主干，比较候选潜变量下的生成效果，最后统计编码、主干计算、解码及缓存的整体成本。重建更好不保证下游生成更好，压缩更强也不保证端到端更划算。

参考资料：[CogVideoX](https://arxiv.org/abs/2408.06072)、[Improved Video VAE](https://arxiv.org/abs/2411.06449)

<h2 id="4.5.2.3_面试问题：不同时长、分辨率和长宽比的视频如何分桶并组成训练批次？">4.5.2.3 面试问题：不同时长、分辨率和长宽比的视频如何分桶并组成训练批次？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

样本分桶（bucketing）是按帧数、分辨率、长宽比等输入规格将样本分组，再从相近规格的样本中组成训练批次的方法。它有助于减少填充（padding）浪费，不同桶也可以根据资源开销使用不同的批次大小。设计分桶时，还需要考虑真实时间跨度和各规格的采样比例，避免只追求批次效率而改变预期训练分布。

分桶通常以实际输入帧数、分辨率和长宽比组织相近形状。视频时长还需结合帧率或采样间隔确定：相同帧数可以对应不同真实时长。帧率影响动作的时间尺度，但不一定需要单独成为分桶维度；可以统一采样帧率，或在模型支持时提供相应时间尺度条件。表5-1 给出了设计 bucket 时应保留的边界。

<p align="center">表5-1 视频训练多规格变量的作用与常见误区</p>

| 变量 | 实际控制的内容 | 常见误区 |
| --- | --- | --- |
| 帧数 $T$ | 输入包含多少个离散时间点，直接影响序列长度 | 把相同帧数当成相同时长 |
| 帧率或采样间隔 | 相邻帧对应的真实时间跨度，影响动作位移和播放速度 | 改变抽帧密度后，模型没有获得相应的时间尺度信息 |
| 分辨率 $H \times W$ | 空间细节、构图以及空间 token 数 | 统一拉伸到固定尺寸，破坏主体比例 |
| 长宽比 | 横竖构图与裁剪范围；它可由 $H,W$ 推出，不是额外独立尺寸 | bucket 过细，产生大量低频规格 |
| latent/patch token 数 | 生成主干看到的实际序列规模 | 只按像素面积估算成本，忽略 VAE 与 patchify |

一套可落地的设计通常按下面的顺序推进：

1. **从目标分布确定主规格。** 先统计训练数据与产品请求中的时长、帧率、分辨率和长宽比，再选择需要重点覆盖的 bucket。数据里存在某种规格，不代表必须等比例训练。
2. **把样本映射到可计算形状。** bucket 尺寸要满足 VAE 和 patchify 的整除或填充规则。分配样本时限制裁剪、缩放和 padding 的幅度，超出阈值的样本应进入其他 bucket 或被单独处理。
3. **逐 bucket 标定 batch size。** token 数可以给出初始估计，最终仍要实测峰值显存和 step time。长序列 bucket 往往需要更小的 batch、更多梯度累积，必要时再配合序列并行。
4. **显式控制采样权重。** 按样本数、按 step 或按 token 采样会得到不同训练分布。低频 bucket 过度采样容易重复，高频 bucket 完全按原始占比又可能挤压业务关键规格，需要记录每类 bucket 的实际曝光量。

bucketing 也不是唯一方案。对不同时长的样本，可以通过 packing 提高利用率；但必须正确处理 attention mask、位置编码和样本边界，避免不同视频之间互相注意。无论采用分桶还是 packing，都应监控 padding 比例、各 bucket 的 samples/s 与 tokens/s、step time 尾延迟、OOM 率和分规格验证质量。

> **面试速答**：分桶先根据目标时长和采样帧率确定帧数，再结合分辨率与长宽比，将样本映射到满足VAE与patch划分约束的形状。帧率影响时间尺度，但不一定单独分桶。不同 bucket 的 batch size 由 token 估算起步，再按实测显存和 step time 标定；同时要显式控制各 bucket 的采样权重。帧数不等于时长，固定总 token 也不保证固定计算量。

参考资料：[CogVideoX](https://arxiv.org/abs/2408.06072)、[NaViT](https://arxiv.org/abs/2307.06304)

<h1 id="4.5.3_视频生成训练策略：图像与视频联合训练、渐进式训练与后训练">4.5.3 视频生成训练策略：图像与视频联合训练、渐进式训练与后训练</h1>

> 本节讨论图像与视频如何联合训练，分辨率、视频长度等规格如何随训练阶段调整，以及基础训练后如何通过高质量数据微调和偏好优化改善生成表现。混合比例与阶段顺序应结合模型初始化、数据质量和验证结果选择，不是所有模型都需要依次经历相同阶段。

<h2 id="4.5.3.1_面试问题：图像与视频联合训练时，如何确定和调整混合比例？">4.5.3.1 面试问题：图像与视频联合训练时，如何确定和调整混合比例？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

图像与视频的混合比例没有通用答案。讨论比例前，必须先说明按什么计数：样本数、训练 step、帧数、token 数还是 loss 权重。一个图像样本和一段视频的 token 量相差很大，“各占一半样本”通常不等于各占一半计算量，也不等于各占一半梯度贡献。

**两类数据提供的监督并不对称。** 在共享空间主干的设定下，图像数据可以补充主体、构图、纹理和文本与视觉的对齐；视频数据还提供动作、时间顺序和帧间一致性。若时间模块在单帧输入上被旁路，图像样本不会直接训练这些参数，但仍会更新共享参数。图像比例提高后，应检查视频数据提供的运动监督是否仍然充分，不能仅凭运动变弱就确定是比例造成的。视频数据质量、loss归一化以及哪些参数实际接收梯度，也会影响单帧质量和运动表现。

**真正需要调的是四个量：**

- 数据加载器采到图像和视频的概率；
- 两类样本消耗的 token 与计算量；
- loss 是按 token、按帧还是按样本归一化；
- 图像路径与视频路径分别更新哪些共享或专用参数。

调节比例时，应把验证集拆成空间质量、文本遵循、运动幅度和时序一致性几类。若图像指标改善而运动持续变弱，先检查视频 token 曝光量和时间模块梯度；若运动改善但单帧细节或文本对齐退化，再检查视频数据质量、共享参数更新幅度和 loss 权重。只比较两类 loss 的数值通常不够，因为它们的归一化尺度可能不同。

混合比例可以随阶段变化，但方向并不固定。从成熟图像模型开始做视频适配时，视频更新通常更关键；从头联合训练时，图像数据也可能改善优化效率。具体比例应由数据质量、初始化方式和分项验证结果决定。

> **面试速答**：图像与视频的混合比例必须先说明按样本、step、token 还是 loss 权重统计。图像主要强化共享空间表示，视频还训练运动和时序；二者对参数与计算量的贡献并不对称。工程上应同时看采样概率、token 曝光、loss 归一化和参数路由，再用空间质量与运动时序的分项验证集调节，不能直接照搬固定比例。

参考资料：[Video Diffusion Models](https://arxiv.org/abs/2204.03458)、[CogVideoX](https://arxiv.org/abs/2408.06072)

<h2 id="4.5.3.2_面试问题：视频生成为什么采用渐进式训练？阶段切换时需要注意什么？">4.5.3.2 面试问题：视频生成为什么采用渐进式训练？阶段切换时需要注意什么？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

渐进式训练（progressive training）是一种训练策略：先在成本较低、信号更容易学习的设定上形成稳定能力，再逐步增加分辨率、视频长度、条件复杂度或数据质量要求。它经常有效，但不是视频模型必须遵守的理论步骤。

**分阶段主要解决两类问题。** 一类是成本：低分辨率、短视频能用更大的有效 batch 和更快的迭代验证基础表示。另一类是优化：如果同时改变时长、分辨率、数据分布和任务条件，训练一旦退化，很难判断是哪项变化造成的。分阶段可以控制变量，也便于在阶段切换后回滚。

常见的阶段关系如图5-2所示。它只是一种组织方式，实际项目可以从已有图像模型、已有视频基座或随机初始化开始，并不要求完整走过所有阶段。

阶段切换比阶段名称更重要，至少要处理下面几项：

- **形状变化**：分辨率和时长提高后，token 规模、位置编码与 batch 组织都会变化，需要重新标定学习率、显存和吞吐；
- **分布变化**：从大规模数据切到精选数据后，质量可能上升，但多样性和长尾能力也可能收缩；
- **优化状态**：是否保留优化器状态、是否重做 warmup、哪些参数解冻，应按变化幅度决定，不能机械继承；
- **放行条件**：阶段切换应依据分项验证是否稳定、目标能力是否达到门槛，而不是只看训练步数或整体 loss。

渐进式训练与课程学习（curriculum learning）有交叉。课程学习强调有计划地安排训练样本或任务的难度；逐步增加视频长度，也可能包含这样的安排。但如果先短后长主要是为了降低早期计算成本，仅凭规格变化还不能说明课程学习带来了收益。

> **面试速答**：progressive training 通过分开引入分辨率、时长、数据质量和任务复杂度，降低早期训练成本，也让阶段退化更容易定位。它不是固定流水线；每次切换都要重新检查 token 规模、学习率、优化器状态和数据分布，并用固定分项验证集决定是否进入下一阶段。课程学习强调样本或任务的难度安排，与渐进式训练可以交叉，但不能仅凭先短后长判断其收益。

参考资料：[Stable Video Diffusion](https://arxiv.org/abs/2311.15127)、[CogVideoX](https://arxiv.org/abs/2408.06072)

<h2 id="4.5.3.3_面试问题：高质量数据微调与偏好优化有什么区别？各自有哪些风险？">4.5.3.3 面试问题：高质量数据微调与偏好优化有什么区别？各自有哪些风险？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

高质量数据微调和偏好优化都发生在基础训练之后，但监督信号不同。高质量数据微调仍用目标视频和条件做生成训练，主要把模型移向更干净、更贴近业务的样本分布；偏好优化利用候选结果之间的比较或奖励信号，提高模型生成更符合偏好的结果的倾向。

两者的职责边界见表5-2。

<p align="center">表5-2 高质量数据微调与偏好优化的监督信号和风险</p>

| 训练阶段 | 主要监督 | 更适合改善 | 主要风险 |
| --- | --- | --- | --- |
| 高质量数据微调 | 精选视频、准确条件及原有 Diffusion/Flow Matching 目标 | 目标领域覆盖、文本遵循、视觉质量和特定失败样本 | 小数据过拟合、能力遗忘、运动或内容多样性收缩 |
| 偏好优化 | 同一条件下的候选排序、人工偏好或经过校准的奖励信号 | 难以用单个目标视频表达的审美、可用性和多目标取舍 | 奖励偏置、过度优化可测指标、输出趋同 |

**“高质量”不能只等同于高分辨率**。数据还要检查动作完整性、时序稳定、caption 准确度、来源分布和业务覆盖。微调集如果大量偏静态，即使单帧画质上升，运动能力也可能回退；如果只保留审美风格相近的样本，生成多样性也会缩小。

**偏好数据同样需要按维度设计**。画质、文本遵循、运动自然度、主体一致性和安全性可能互相冲突，把它们压成一个未经校准的总分，模型容易沿评估器的偏好取巧。DPO、reward-weighted training 或带奖励的优化只是实现方式，核心仍是偏好数据是否覆盖真实产品取舍，以及训练是否受参考模型或其他约束限制。

更稳妥的验证方式是保留基础能力回归集，并同时观察偏好胜率、运动幅度、内容多样性、文本遵循和严重失败率。偏好分数提高但视频越来越静、构图越来越相似，通常说明模型在迎合评估信号，不能视为整体质量提升。

> **面试速答**：高质量数据微调用精选视频继续原有生成目标，主要调整模型的数据分布；偏好优化用候选比较或奖励信号，提高模型生成更符合偏好的结果的倾向。前者要防止小数据过拟合和能力遗忘，后者要防止奖励偏置、输出趋同和运动静态化。两者都应保留基础能力回归集，偏好分数提高不能单独证明模型整体变好。

参考资料：[Stable Video Diffusion](https://arxiv.org/abs/2311.15127)、[Improving Video Generation with Human Feedback](https://arxiv.org/abs/2501.13918)

<h1 id="4.5.4_视频生成训练目标与优化：Diffusion、Flow-Matching与异常排查">4.5.4 视频生成训练目标与优化：Diffusion、Flow Matching与异常排查</h1>

> 本节讨论Diffusion与Flow Matching的训练目标、条件丢弃和损失加权等设置，以及数值异常与生成质量退化的排查方法。需要明确每项设置改变了什么，并检查视频潜变量尺度、不同规格的损失归一化和运动时序表现。训练阶段安排见4.5.3，计算、显存与分布式效率问题见4.5.5。

<h2 id="4.5.4.1_面试问题：视频生成训练出现数值异常或生成质量退化时，如何排查？">4.5.4.1 面试问题：视频生成训练出现数值异常或生成质量退化时，如何排查？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

判断视频训练是否稳定，不能只看一条平均 loss。先按表5-3把现象分层，才能选择有效的最小实验。

<p align="center">表5-3 视频生成训练异常的分层定位</p>

| 现象层 | 典型信号 | 优先检查 | 最小验证 |
| --- | --- | --- | --- |
| 数值异常 | loss 或梯度出现 NaN/Inf，动态 loss scale 连续下降 | 异常 batch、学习率、混合精度、归一化与梯度裁剪 | 保存首个异常 step 的输入，用更高精度和单卡短跑复现 |
| 优化失衡 | 总 loss 波动或下降缓慢，某些时间步、规格或任务梯度长期占优 | timestep 分布、loss 权重、token 归一化、阶段切换 | 固定数据和模型，单独改变一个采样或权重变量 |
| 表示或数据异常 | loss 看似正常，但特定 bucket 持续闪烁、静态化或出现伪影 | VAE 重建与 latent 统计、坏样本率、caption、帧率和切片 | 对同一批视频比较原视频、VAE 重建和生成结果 |
| 评估回退 | 训练 loss 下降，固定提示集的画质、运动或文本遵循变差 | EMA/原始权重、采样器、CFG、验证配置与数据分布 | 固定 prompt、seed 和采样参数，对相邻 checkpoint 做回放 |

若主要表现为训练耗时增加、显存不足或通信等待，应转到4.5.5检查系统效率；本题重点排查数值与生成质量异常。

可以按以下顺序排查：

1. **先让问题可复现。** 固定 checkpoint、EMA 或原始权重、prompt、seed、采样器和 CFG，避免把评估配置变化误判为训练退化。
2. **找到第一个异常点。** 对齐当时的 batch、bucket、学习率、loss scale、梯度范数和配置变更。只看异常后的长期曲线，常常已经错过触发原因。
3. **缩小到单一变量。** 用单 bucket、固定小数据集或短时间高精度运行验证假设。若连小数据都无法拟合，优先查实现和数值；若小数据正常而全量训练异常，再回到数据分布、采样和分布式一致性。
4. **修复后做回归。** 除整体 loss 外，还要复查单帧质量、运动幅度、时序一致性、文本遵循及不同规格的失败率。

训练 loss 只能说明当前目标函数上的平均误差。它可能掩盖时间步、分辨率和数据子集之间的差异，也不能代替生成端验证。

> **面试速答**：视频训练异常可从数值发散、优化失衡、数据或latent异常、生成评估回退等方面检查。排查时固定生成配置，定位第一个异常 step，再用单 bucket、固定小数据或高精度短跑验证单一假设。总 loss 正常不能排除运动、时序或文本遵循已经回退，step time 和 OOM 则应单独进入系统链路排查。

参考资料：[Elucidating the Design Space of Diffusion-Based Generative Models](https://arxiv.org/abs/2206.00364)、[CogVideoX](https://arxiv.org/abs/2408.06072)

<h2 id="4.5.4.2_面试问题：采用Diffusion或Flow-Matching训练视频模型时，需要核对哪些关键设置？">4.5.4.2 面试问题：采用Diffusion或Flow Matching训练视频模型时，需要核对哪些关键设置？</h2>

**难度评分：⭐⭐⭐⭐⭐ (5/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

Diffusion 与 Flow Matching 都可以训练网络把噪声分布连接到数据分布，差别主要在概率路径、监督目标和采样动力学。二者并非完全互斥：Flow Matching 可以使用扩散概率路径，Rectified Flow 则是更具体的一类路径设计。

Diffusion 先定义加噪过程，例如：

```math
x_t=\alpha(t)x_0+\sigma(t)\epsilon,
\qquad \epsilon\sim\mathcal{N}(0,I)
```

其中 $x_0$ 是干净视频 latent，$x_t$ 是时间 $t$ 的带噪状态，$\alpha(t)$ 和 $\sigma(t)$ 控制信号与噪声强度。网络可以预测噪声 $\epsilon$、干净样本 $x_0$、速度参数化 $v$ 或其他等价目标，不能把 Diffusion 限定为“预测噪声”。训练表现会受到噪声调度、输入预条件、预测参数化、时间步采样和 loss weighting 的共同影响；推理时还要让 sampler 与训练时的参数化和噪声定义一致。

Flow Matching 选定连接两端分布的概率路径，并回归该路径上的条件速度场：

```math
\mathcal{L}_{\text{fm}}=
\mathbb{E}_{t,x_t}
\left[
w(t)\lVert v_\theta(x_t,t,c)-u_t(x_t)\rVert_2^2
\right]
```

其中 $x_t$ 从选定的概率路径采样，$c$ 是文本等生成条件，$u_t$ 是目标路径在时间 $t$ 的条件速度，$v_\theta$ 是模型预测，$w(t)$ 是可选权重。工程上要关注路径与样本配对、时间参数化、速度场尺度，以及 ODE 求解器的步数、离散方式和误差。路径更直不等于任意模型都能稳定少步生成，最终效果仍受网络逼近误差和求解器影响。

在视频训练里，两条路线还共享相同的基础风险：VAE latent 尺度不一致、不同视频规格的 loss 归一化不一致、时间采样覆盖失衡，以及训练目标改善但运动质量没有同步提升。公平比较时应固定数据、VAE、backbone、训练算力和采样网络调用次数，再分别观察收敛速度、数值异常率、单帧质量、运动与时序质量。只更换目标函数却同时更换模型和 sampler，无法判断收益来自哪里。

> **面试速答**：Diffusion 先定义加噪过程，可预测噪声、$x_0$ 或 $v$ 等目标；Flow Matching 直接回归选定概率路径上的速度场。FM 可以采用扩散路径，因此两者不是简单对立。Diffusion 侧重噪声调度、预条件、预测参数化和 sampler 对齐，FM 侧重路径、时间参数化与 ODE 求解；谁更稳定或更适合少步采样，必须在固定数据、主干和计算预算下实测。

参考资料：[Flow Matching for Generative Modeling](https://arxiv.org/abs/2210.02747)、[Elucidating the Design Space of Diffusion-Based Generative Models](https://arxiv.org/abs/2206.00364)

<h2 id="4.5.4.3_面试问题：条件丢弃、EMA、时间步采样和损失加权分别起什么作用？">4.5.4.3 面试问题：条件丢弃、EMA、时间步采样和损失加权分别起什么作用？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

这四项设置作用不同：条件丢弃用于训练空条件预测，EMA维护平均权重，时间步采样决定抽取哪些噪声或路径位置，损失加权调整不同训练项的贡献。这里的“时间步”指扩散或流路径中的时间变量，不是视频中的帧时间。

**条件丢弃（condition dropout）：让同一模型学会条件与无条件预测。** 训练时以一定概率把条件替换为空条件，推理时才能组合两路输出：

```math
f_{\mathrm{cfg}}
=f_\theta(x_t,t,\varnothing)
+s\left[f_\theta(x_t,t,c)-f_\theta(x_t,t,\varnothing)\right]
```

其中 $c$ 表示生成条件，$\varnothing$ 表示空条件；$f_\theta$ 可以是当前参数化下的噪声、速度或其他预测，$s$ 是 guidance scale。dropout 太少，无条件分支可能不可靠；太多则会减少条件样本的训练曝光。多条件系统还要区分“全部条件一起丢弃”和“每种条件独立丢弃”，两者训练出的可组合能力不同。验证时应画出 guidance scale 扫描曲线，同时看文本遵循、运动、伪影和多样性。

**EMA：提供一份参数的滑动平均副本。**

```math
\bar{\theta}\leftarrow \beta\bar{\theta}+(1-\beta)\theta
```

EMA 不参与当前参数 $\theta$ 的梯度更新，因此不能用来修复 loss 爆炸或错误梯度。它主要用于评估或发布更平滑的权重，并带来额外参数存储。衰减过大时会明显滞后于当前模型，阶段切换后尤其要比较原始权重与 EMA 权重，避免把滞后误判成训练回退。

**时间步采样（timestep sampling）：决定噪声或路径位置的采样分布。** 若从分布 $q(t)$ 非均匀采样并加入正确的重要性修正，可以估计原目标；不做修正时，实际优化目标就被改变。它主要影响训练方差、收敛速度以及模型更常看到哪些噪声或路径区间。

**损失加权（loss weighting）：调整不同训练项的梯度贡献。** 权重可以按 SNR、时间步、帧、区域、任务或样本规格设置。它必须与预测参数化和 loss 归一化一起设计；照搬另一种参数化下的权重，可能让某些时间区间主导训练。

timestep sampling 与 loss weighting 会共同决定有效梯度分布。若时间位置按 $q(t)$ 抽样、loss 使用 $w(t)$，未做其他修正时，该位置的相对贡献与 $q(t)w(t)$ 有关。因此两者不宜同时改完再看总 loss，至少要记录分时间步 loss、梯度范数和生成切片，逐项做消融。

> **面试速答**：CFG dropout 训练条件与无条件两路预测，为推理时的 CFG 提供基础；EMA 只维护平滑权重副本，不会修复当前训练的数值发散；timestep sampling 决定时间位置出现的频率，loss weighting 决定出现后贡献多大梯度。后二者的有效作用相互耦合，必须结合预测参数化和分时间步统计调节。

参考资料：[Classifier-Free Diffusion Guidance](https://arxiv.org/abs/2207.12598)、[Efficient Diffusion Training via Min-SNR Weighting Strategy](https://arxiv.org/abs/2303.09556)、[Elucidating the Design Space of Diffusion-Based Generative Models](https://arxiv.org/abs/2206.00364)

<h1 id="4.5.5_视频生成训练效率：吞吐瓶颈、显存优化与并行策略">4.5.5 视频生成训练效率：吞吐瓶颈、显存优化与并行策略</h1>

> 本节讨论视频生成训练的吞吐瓶颈、显存占用与并行策略。长时空序列、多规格样本和在线VAE编码会带来不同的资源开销，需要结合阶段耗时、显存峰值和设备间负载选择优化方法。数据供给链路见4.5.1，训练规格与批次组织见4.5.2，本节关注它们与计算、通信共同决定的整体效率。

<h2 id="4.5.5.1_面试问题：视频训练吞吐低，应该从哪些环节排查？">4.5.5.1 面试问题：视频训练吞吐低，应该从哪些环节排查？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

**吞吐指标先统一。** samples/s 会把短视频和长视频视为同一个样本，原始 tokens/s 又可能把 padding 算作有效工作。视频训练更适合同时记录有效视频 tokens/s、step time 的 p50/p95、各 rank 到达同步点的时间差以及 padding 比例，再用 samples/s 说明样本处理速度。有效tokens/s适合在模型、token定义和训练规格可比时观察效率，不能直接用于不同架构之间的统一排名。

**定位时沿关键路径收缩范围。** 可以按下面四步进行：

1. **先确认 GPU 是否在等数据。** 对比 dataloader wait、Host-to-Device 拷贝时间和 GPU timeline；再用合成 latent 或内存缓存数据短跑。如果吞吐明显上升，继续检查存储、解码、在线 VAE 和 bucket。完整的数据链路定位见 4.5.1.1，本节不再重复。
2. **再拆分单步计算。** 分开统计前向、反向、激活重算和优化器更新时间，查看 attention、矩阵乘和大量小算子各占多少。GPU 利用率高也可能只是反复重算或运行低效率 kernel，因此还要比较关闭 checkpointing、替换 attention kernel 等单变量实验。
3. **判断通信是否暴露在关键路径上。** 在模型能够运行的范围内，比较单卡、单机多卡和多机吞吐，并明确每卡工作量和全局批次是否改变。例如，数据并行扩展时固定每卡工作量，会随设备数增加全局批次；使用张量或长序列并行时，多张卡共同处理同一样本，不能直接套用这一口径。单机扩展正常、多机明显下降，通常要继续检查 all-reduce、all-gather、reduce-scatter 的耗时，通信与计算是否重叠，以及网络拓扑与并行组是否匹配。
4. **检查负载不均与周期性停顿。** 比较各 rank 的 token 数、计算时间和同步等待时间。某个 bucket 过长、坏节点、保存 checkpoint 或数据分片倾斜，都会让其余 rank 等待最慢者；只看平均 step time 容易漏掉这类长尾。

**优化效果看端到端。** 某项优化即使缩短了一个 kernel，只要引入更多 padding、通信或重算，整体训练速度仍可能下降。

> **面试速答**：先用有效视频 tokens/s 和 step time 分位数确认问题，再做分层替换：合成 latent 隔离数据供给，单卡到多机的扩展实验隔离通信，逐 rank timeline 定位负载不均。GPU 利用率只能辅助判断，高利用率也可能来自无效 padding、重算或低效率 kernel。

参考资料：[PyTorch Profiler](https://docs.pytorch.org/docs/stable/profiler.html)、[FlashAttention](https://arxiv.org/abs/2205.14135)

<h2 id="4.5.5.2_面试问题：视频生成模型训练时，如何定位显存占用并选择优化方法？">4.5.5.2 面试问题：视频生成模型训练时，如何定位显存占用并选择优化方法？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

**先定位显存峰值。** 前向阶段达到峰值，通常先查输入规格、padding、激活和 attention 临时量；反向峰值更可能与保存的激活、梯度和重算策略有关；优化器更新或保存 checkpoint 时溢出，则要检查优化器状态、参数聚合和 state dict 的生成方式。只有分清峰值来源，优化手段才不会错位。

**再判断显存花在了哪里。** 参数、梯度和优化器状态属于**模型状态**；随 micro-batch、token 数和层数变化的部分主要是**激活**；attention workspace、通信 buffer、内存碎片等属于**临时开销**。表5-4 给出了常见方案实际作用的位置。

<p align="center">表5-4 视频模型训练中的主要显存优化手段</p>

| 方法 | 主要减少的显存 | 主要代价或边界 |
| --- | --- | --- |
| BF16/FP16，必要时 FP8 | 参数计算副本、激活和部分通信量 | FP8 依赖硬件与算子支持，还要验证量化尺度和数值稳定性 |
| memory-efficient attention | attention 中间量及 HBM 读写 | 不改变稠密 attention 的理论计算量；具体收益受形状和 kernel 支持影响 |
| activation checkpointing | 反向所需的保存激活 | 反向阶段增加重算，checkpoint 粒度过细还会增加调度开销 |
| FSDP/ZeRO | 参数、梯度和优化器状态的冗余副本 | 引入参数聚合与梯度切分通信，也会产生短时的未切分参数峰值 |
| context/sequence parallel | 长序列相关的激活；具体范围取决于实现 | 需要额外通信，且 sequence parallel 在不同框架中的语义并不相同 |
| CPU/NVMe offload | GPU 上的模型状态或激活 | 把压力转移到主存、PCIe 或存储带宽，通常会牺牲吞吐 |

**优化顺序取决于占用来源。** 实际调整时可以按下面的顺序推进：

1. **消除无效占用。** 先处理过度 padding、异常大的 bucket 和不必要的在线 VAE。VAE latent 预计算只会移除在线编码的计算和工作区；如果 VAE 原本已冻结并在 `no_grad` 下运行，就不能把它描述为节省生成主干的激活显存。
2. **降低激活开销。** 常见组合是低精度、memory-efficient attention 和分层 activation checkpointing，并根据吞吐损失选择重算粒度。
3. **切分模型状态。** 若参数、梯度和优化器状态仍占主导，再引入 FSDP 或 ZeRO，并检查参数聚合造成的临时峰值和通信开销。
4. **处理超长单样本。** 长视频的单样本激活仍然放不下时，再使用 context parallel 等序列维度切分。

**单独看 micro-batch 的作用。** 减小 micro-batch 确实能降低激活显存，但不会减少参数和优化器状态。可以用梯度累积维持全局 batch，代价是单次参数更新需要更多前后向；如果连全局 batch 也一起改变，还要重新核对学习率、优化器统计和收敛表现。

> **面试速答**：先按 OOM 出现位置判断峰值来自模型状态、激活还是临时 buffer。激活侧优先检查 padding、低精度、memory-efficient attention 和 checkpointing；状态侧使用 FSDP/ZeRO；超长序列再考虑 context parallel。减 micro-batch 只解决激活峰值，不能替代显存归因。

参考资料：[FlashAttention](https://arxiv.org/abs/2205.14135)、[ZeRO](https://arxiv.org/abs/1910.02054)、[PyTorch FSDP](https://docs.pytorch.org/docs/stable/fsdp.html)

<h2 id="4.5.5.3_面试问题：视频生成模型训练时，如何选择和组合数据并行、张量并行与长序列并行？">4.5.5.3 面试问题：视频生成模型训练时，如何选择和组合数据并行、张量并行与长序列并行？</h2>

**难度评分：⭐⭐⭐⭐⭐ (5/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

**先认清并行轴。** FSDP 是分片数据并行的实现，和普通 DDP 同属数据并行这一侧，不能把“Data Parallel + FSDP”当成两个独立维度直接相乘。Tensor Parallel（TP）让多张卡共同完成一层的矩阵计算；长序列切分则让多张卡共同处理同一个视频样本。

“Sequence Parallel”还要说明具体框架。Megatron 语境下的 SP 通常与 TP 配套，只沿序列维切分 LayerNorm、Dropout 等区域的激活；把整个输入和各层激活沿序列维切分、并在 attention 中交换 KV，Megatron 称为 Context Parallel（CP）。其他论文或框架可能把后一类方案也叫 sequence parallel。面试时先给出实现语义，比只报名称更可靠。

**选择依据是实际瓶颈。** 以下方法分别对应不同的资源问题，可以按需组合，不是必须依次尝试的升级顺序：

1. **单卡能容纳模型状态和目标微批次时，可用普通数据并行（DDP）扩展吞吐。** 各卡处理不同样本，主要通过梯度同步保持模型一致。
2. **模型状态放不下时，在数据并行维度使用 FSDP/ZeRO。** 参数在计算前需要聚合，梯度在反向后切分，因此要同时测显存峰值和暴露在关键路径上的通信。
3. **单层权重过大或层内计算需要多卡分担时，可使用张量并行（TP）。** TP 通信频繁，通常优先放在 NVLink/NVSwitch 等高带宽域内。
4. **单个视频的时空序列导致激活或 attention 超限时，使用 CP 或框架对应的长序列并行。** 它解决的是单样本长度，不应由减小 batch 替代；同时要验证位置编码、mask 和跨 rank attention 是否正确。

**设备数和全局 batch 要分开算。** 不考虑流水线并行时，两者可以写成：

```math
G=D\times T\times C,
\qquad
B_{\mathrm{global}}=B_{\mathrm{micro}}\times A\times D
```

其中 $T$、$C$ 分别是 TP 和 CP 规模，它们共同处理同一批样本；$D$ 是独立处理数据的并行规模，可以由 DDP 或 FSDP 实现；$A$ 是梯度累积步数。因此增加 TP 或 CP 不会自动放大全局 batch。若再加入 Pipeline Parallel，则设备数还要乘流水线级数，并单独处理流水线气泡。

**并行组还要服从硬件拓扑。** 一种常见但非固定的映射见图5-3：把通信频繁的 TP/CP 组放在节点内，把数据并行或分片数据并行扩展到节点间。最终仍要依据节点内外带宽、模型形状和集合通信实测决定。

  <img src="./imgs/ch05/fig-5-03-video-dit-parallel-groups.png" alt="两台多 GPU 节点内部以 TP 和 CP 切分同一样本的层内计算与长序列，节点之间以 DDP 或 FSDP 扩展数据并行维度" width="780">
  <p>图5-3 视频 DiT 混合并行的进程组与硬件映射</p>
</div>

**大规模训练前先验证正确性。** 应在小模型上做单卡与多卡数值对齐，核对 loss、梯度、随机数和样本切分；再检查峰值显存、通信时间、扩展效率和分布式 checkpoint 的保存与恢复。能启动训练不代表并行组已经配置正确。

> **面试速答**：DDP 与 FSDP 属于同一数据并行维度，FSDP 通过切分模型状态换显存；TP 切分层内计算，CP 切分同一视频的长序列。模型状态可用FSDP等方式分片，单层计算可用TP分担，单样本长序列可用CP切分；应按实际瓶颈和通信代价选择组合。TP/CP 规模不计入全局 batch 的放大倍数，并行组还要按节点带宽映射并做数值对齐。

参考资料：[ZeRO](https://arxiv.org/abs/1910.02054)、[Reducing Activation Recomputation in Large Transformer Models](https://arxiv.org/abs/2205.05198)、[Megatron Core Parallelism Strategies Guide](https://docs.nvidia.com/megatron-core/developer-guide/latest/user-guide/parallelism-guide.html)、[PyTorch FSDP](https://docs.pytorch.org/docs/stable/fsdp.html)

<h1 id="4.5.6_视频生成推理与部署优化：延迟、吞吐与成本">4.5.6 视频生成推理与部署优化：延迟、吞吐与成本</h1>

> 本节讨论视频生成请求从进入服务到交付结果的耗时，以及采样、单步计算、VAE解码和服务调度的优化方法。优化应在满足生成质量要求的前提下，比较端到端延迟、服务吞吐与成功交付成本。模型组件及推理流程见第二章，本节重点分析实际运行中的资源开销与取舍。

<h2 id="4.5.6.1_面试问题：视频生成请求的端到端延迟由哪些部分构成？如何定位瓶颈？">4.5.6.1 面试问题：视频生成请求的端到端延迟由哪些部分构成？如何定位瓶颈？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

线上延迟由排队时间和一次请求经过的执行链路共同决定。对于典型的 latent 视频生成系统，可近似写成：

```math
L_{\mathrm{e2e}}\approx
L_{\mathrm{queue}}
+L_{\mathrm{condition}}
+\sum_{s=1}^{S}L_{\mathrm{denoise}}^{(s)}
+L_{\mathrm{VAE}}
+L_{\mathrm{post}}
+L_{\mathrm{encode/transfer}}
```

其中 $S$ 是去噪步数。该式按串行链路近似；如果安全检查、编码或传输存在并行，端到端时间应按实际关键路径统计，不能简单相加。

**排队和请求准备。** 请求进入模型前，可能经历限流、规格校验、prompt 处理、参考图上传以及文本或图像条件编码。高并发下，队列等待可能超过模型执行时间；条件编码若与 DiT、VAE 共用同一组 GPU，也可能因阶段负载不均造成设备空转。

**重复去噪。** DiT 会对整段时空 latent 重复执行 $S$ 次，单步成本受帧数、分辨率、patch 大小、attention 形式和并行通信影响。启用 CFG 时，条件与无条件分支通常还会增加模型计算；合并进同一次 batched forward 可以提高并行度，但不会消除额外的计算量和显存占用。

**解码和结果交付。** 3D VAE 解码、高分辨率后处理、安全检查、视频编码以及上传下载都可能进入关键路径。分块解码能降低显存峰值，但会增加调度和边界处理；主干加速以后，瓶颈还可能转移到 VAE 或视频编码。

**定位时按阶段打点。** 固定模型、输出规格、采样配置和并发量，分别记录 queue、condition、单步及总去噪、VAE、后处理、编码与传输的 p50/p95，配合 GPU timeline、显存峰值、batch 填充率和失败原因定位长尾。若支持预览或流式返回，再单独记录首个可用结果时间；它不适合替代完整视频交付时间。

> **面试速答**：视频生成的端到端延迟包含排队、条件编码、多步去噪、VAE 解码、后处理、视频编码和传输。去噪通常占大头，但高并发、长视频或主干加速后，瓶颈可能转移到队列、VAE 和编码。排查时要固定请求规格，对每个阶段记录 p50/p95、显存和失败原因，不能用 GPU 利用率或单步耗时代表整条链路。

参考资料：[CogVideoX](https://arxiv.org/abs/2408.06072)、[DDiT](https://arxiv.org/abs/2506.13497)、[PyTorch Profiler](https://docs.pytorch.org/docs/stable/profiler.html)

<h2 id="4.5.6.2_面试问题：视频生成推理有哪些加速方法？各自的收益与代价是什么？">4.5.6.2 面试问题：视频生成推理有哪些加速方法？各自的收益与代价是什么？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

推理加速要先确定瓶颈发生在哪个阶段，再选择对应手段。减少去噪步数、加快单步计算、降低解码成本和提高并发吞吐是不同目标，不能只比较一个“加速倍数”。各路线的作用位置和代价见表5-5。

<p align="center">表5-5 视频生成推理加速路线及其适用边界</p>

| 路线 | 主要改善 | 代价或适用边界 |
| --- | --- | --- |
| 更合适的 sampler 或 solver、减少步数 | 减少主干调用次数，直接降低去噪延迟 | 原模型未针对极少步训练时，细节、运动和条件遵循可能退化；采样器要与训练参数化匹配 |
| 蒸馏或 consistency 训练 | 把多步教师压缩为少步学生 | 需要额外训练与数据，可能改变多样性、CFG 响应和不同任务上的质量分布 |
| BF16/FP16/FP8、优化 attention kernel、编译与算子融合 | 降低每一步的计算、访存或调度开销 | 收益依赖硬件、输入形状和算子覆盖；低精度还要验证数值与质量 |
| 条件编码缓存、跨去噪步特征复用 | 避免重复条件计算或近邻步骤中的部分重复计算 | 固定条件的编码结果通常可以精确复用；跨步中间特征复用多为近似方法，受架构和缓存间隔影响 |
| VAE 专用解码优化、并行、分块或时间切片 | 专用优化与合理并行可缩短解码时间；分块和切片主要降低峰值显存 | 分块和切片常以更多调度换显存，可能降低速度；还要检查接缝、时间边界和通信成本 |
| 多 GPU 模型、序列或空间并行 | 让单卡放不下的模型或长视频运行，并尝试降低单请求延迟 | 通信可能抵消计算收益，并行度越高不代表延迟越低 |
| 按形状分桶和动态 batching | 提高设备占用与整体吞吐 | 等待组 batch 会增加排队时间；帧数、分辨率或采样配置不一致时，还会产生 padding 浪费或无法直接合批 |

**优化顺序从可测量的瓶颈开始。** 先建立逐阶段基线，再处理无需改变模型目标的低风险项，例如匹配硬件的精度、attention kernel、编译和条件缓存；随后评估少步采样、蒸馏或跨步特征复用等会改变生成分布的方案。显存不足时，VAE 分块、offload 或多卡并行可能让任务跑起来，但它们不一定降低延迟。

验证时应固定 prompt 与 seed 集合、帧数、分辨率和并发压力，同时比较端到端 p50/p95、吞吐、峰值显存、单位成本、失败率以及画质、运动和条件遵循。详细的质量评估方法见 4.5.7；本题只负责判断加速收益是否建立在可接受的质量代价上。

> **面试速答**：推理加速分为减少去噪次数、降低单步成本、优化 VAE、使用缓存或并行，以及通过 batching 提高吞吐。条件编码缓存可以精确复用，跨去噪步特征缓存通常是近似加速；VAE 分块主要解决显存，也可能变慢。所有方案都要回到端到端延迟、吞吐、峰值显存、失败率和分项质量上比较。

参考资料：[Progressive Distillation for Fast Sampling of Diffusion Models](https://arxiv.org/abs/2202.00512)、[Latent Consistency Models](https://arxiv.org/abs/2310.04378)、[FlashAttention](https://arxiv.org/abs/2205.14135)、[DeepCache](https://arxiv.org/abs/2312.00858)、[DDiT](https://arxiv.org/abs/2506.13497)

<h2 id="4.5.6.3_面试问题：视频生成服务如何兼顾质量、延迟、吞吐与成本？">4.5.6.3 面试问题：视频生成服务如何兼顾质量、延迟、吞吐与成本？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

服务设计应先明确质量门槛、延迟目标、并发需求与成本预算，再选择模型配置和调度方式。请求需求差异较大时，可以设置服务档位或分开调度；需求相近时，也可以使用统一配置与队列，不必预设多个档位。

**根据请求需求选择交付方式。** 需要快速反馈时，可以提供低分辨率、短时长或少步模型生成的预览；对质量要求较高、执行时间较长的任务，可以采用异步交付。如果采用预览、标准和高质量等档位，各档配置都需要单独验证，不能只按采样步数划分，也不能假定增加步数一定提高质量。

**请求进入队列前先估算负载。** 根据模型版本、帧数、分辨率、去噪步数和控制条件估算 token、显存与运行时间，再按形状分桶，路由到对应资源池。高、低优先级请求若共用一条无界队列，长任务很容易阻塞短任务。图5-4给出了一种按请求需求分开路由的示例，是否使用独立资源池应结合流量规模和资源利用率决定。

  <img src="./imgs/ch05/fig-5-04-serving-tier-routing.png" alt="视频生成请求经规格校验和负载估算后分层进入预览、标准、高质量和长视频资源池，再经过模型、VAE、安全审核、编码与交付，并区分 OOM、超时和取消的有限回退" width="780">

**失败处理要区分原因。** OOM 可以降低规格、切换更大显存资源或改用分块解码；超时可以转入异步队列或在预算内重试；用户取消后应尽快释放队列和 GPU 任务。重试必须设置次数与成本上限，并保证请求幂等。安全审核失败不能通过降低审核标准来提高成功率，应返回明确状态，再按策略拒绝、重新生成或终止。

**成本按成功交付统计。** 除 GPU 执行时间外，还要计入 padding、空闲、失败重试、VAE 与编码、存储和传输。请求数/s 无法公平比较长短不同的视频，可以同时记录成功请求吞吐、每 GPU 小时交付的视频秒数、每成功视频秒成本，以及 queue time 和 service time 的 p50/p95。这些成本与吞吐指标应在输出分辨率、帧率、质量要求及请求构成可比时比较，不能仅按视频秒数判断不同服务配置的优劣。质量门槛和灰度发布方法见 4.5.7，本题重点是让调度、回退和成本口径与这些门槛一致。

> **面试速答**：先明确质量、延迟、容量与成本目标，再根据模型版本、帧数、分辨率和采样配置估算请求负载。按需采用请求合批、队列隔离、服务分档或异步交付，失败重试设置次数与成本上限。最终在可比输出规格和质量要求下，检查成功交付吞吐、延迟、失败率与单位成本。

参考资料：[DDiT](https://arxiv.org/abs/2506.13497)、[NVIDIA Triton Inference Server: Dynamic Batching](https://docs.nvidia.com/deeplearning/triton-inference-server/user-guide/docs/user_guide/batcher.html)

<h1 id="4.5.7_视频生成质量评估：评估维度、评审方法与迭代验证">4.5.7 视频生成质量评估：评估维度、评审方法与迭代验证</h1>

> 本节讨论视频生成质量的评估维度、自动指标与人工及模型评审的分工，以及如何用评估结果选择模型版本、检查发布条件和验证问题修复。长视频的观察范围与事件检查见4.4.6，推理调度与成本优化见4.5.6；这里重点保证评估结果可信，并能支持后续迭代。

<h2 id="4.5.7.1_面试问题：为什么视频生成不能依赖单一指标判断模型好坏？">4.5.7.1 面试问题：为什么视频生成不能依赖单一指标判断模型好坏？</h2>

**难度评分：⭐⭐⭐⭐ (4/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

单一指标只能观察视频质量的一个投影。画面、运动、条件遵循、长程一致性和多样性可能朝不同方向变化；把它们压成一个总分，会掩盖严重退化发生在哪个维度。

常见自动指标的职责边界见表5-6。

<p align="center">表5-6 常见视频生成自动指标的能力边界</p>

| 指标类型 | 主要观察对象 | 无法单独回答的问题 |
| --- | --- | --- |
| 分布距离，如 FVD | 生成集与参考集在视频特征空间中的分布差异 | 单条视频是否正确、是否遵循 prompt；结果还受样本数、预处理和特征提取器影响 |
| 文本—视频相似度 | 视频与文本的整体语义相关性 | 数量、空间关系、动作方向和事件顺序是否准确 |
| 帧级画质或美学分数 | 清晰度、伪影和单帧观感 | 闪烁、身份漂移、运动是否自然 |
| 光流、跟踪或时序指标 | 局部运动、轨迹稳定性和帧间变化 | 运动是否符合指令，静止视频是否只是通过少运动获得高分 |

**FVD 应该怎么用。** FVD 是集合级统计量，不适合解释单条视频。原始工作报告了它与人类判断的相关性，后续研究也指出其对特征空间、时间扰动和样本规模存在敏感性。这两类结论并不矛盾：FVD 可以作为固定协议下的趋势信号，但不能独立承担模型发布决策。

**工程比较需要固定评测协议。** prompt 集、生成数量、seed、帧率、时长、分辨率、采样配置、预处理和指标实现版本都要保持一致。协议不同，即使指标名称相同，数值也未必可直接横向比较。最终应保留分维得分和失败样本，严重安全或一致性问题使用硬门槛处理，不让加权总分把它抵消。

> **面试速答**：单一指标只覆盖视频质量的一部分。FVD 看生成集与参考集的分布差异，文本相似度看整体语义，帧级指标看空间质量，运动指标看局部时间变化；它们都不能单独判断一条视频是否完成了任务。可靠结论需要固定评测协议，同时查看分维指标、场景分桶和失败样本，关键问题再用人评校准。

参考资料：[Towards Accurate Generative Models of Video](https://arxiv.org/abs/1812.01717)、[Beyond FVD](https://arxiv.org/abs/2410.05203)、[VBench](https://arxiv.org/abs/2311.17982)

<h2 id="4.5.7.2_面试问题：视频生成质量评估应覆盖哪些维度？如何针对不同任务补充？">4.5.7.2 面试问题：视频生成质量评估应覆盖哪些维度？如何针对不同任务补充？</h2>

**难度评分：⭐⭐⭐⭐⭐ (5/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

评估维度应围绕输出能力定义，与具体 backbone、训练目标和产品版本解耦。表5-7 给出了一组适用于多数视频生成任务的基础维度。

<p align="center">表5-7 视频生成评估的基础能力维度</p>

| 能力维度 | 核心问题 | 典型失败现象 |
| --- | --- | --- |
| 空间与视觉质量 | 每一帧是否清晰、结构合理且没有明显生成伪影 | 模糊、局部畸形、纹理破碎、文字不可读 |
| 运动与短时时序 | 运动幅度、速度和帧间变化是否自然稳定 | 闪烁、抖动、动作冻结、速度突变 |
| 条件遵循 | 是否满足文本、参考图、首尾帧、姿态或轨迹等条件 | 漏对象、属性绑定错误、动作方向或空间关系错误 |
| 主体、场景与状态保持 | 身份、背景和已发生事件能否跨时间持续 | 换脸、换装、物体消失、状态回滚、场景漂移 |
| 几何、交互与物理可信度 | 遮挡、接触、碰撞和空间关系是否合理 | 穿模、悬浮、接触错位、物体无因变化 |
| 多样性与分布覆盖 | 多个 seed 是否覆盖合理解，而非收缩到少数安全模板 | 构图趋同、运动静态化、长尾概念缺失 |

**具体任务还要增加对应约束。** T2V 重点检查文本中的对象、属性、关系和动作；I2V 还要检查参考主体与首帧连续性；V2V 要同时检查编辑准确度和非编辑区域保持；长视频关注状态、事件顺序和分段边界；联合音视频任务还要增加音画同步。长视频专项可参考 4.4.6。

**评测集需要按场景和难度分桶。** 例如静态与高运动、单主体与多主体、简单与组合指令、短视频与长视频、普通场景与复杂交互。每个维度都要有针对性的 prompt、评分方法和失败标签。安全、合规、延迟、失败率和成本属于发布约束，应与生成能力共同决策，但不宜混入同一张“画质总分”中。

> **面试速答**：基础评估至少覆盖空间质量、运动时序、条件遵循、主体与状态保持、几何物理可信度以及多样性。不同任务再增加对应约束：I2V 看参考保持，V2V 看编辑区域与非编辑区域，长视频看状态和事件连续，音视频看同步。评估维度、任务分组和失败标签应保留可追溯的版本，并随新任务补充；比较版本时需明确评估范围是否一致。

参考资料：[VBench](https://arxiv.org/abs/2311.17982)、[EvalCrafter](https://arxiv.org/abs/2310.11440)、[VBench++](https://arxiv.org/abs/2411.13503)

<h2 id="4.5.7.3_面试问题：自动指标、人类评测和多模态大模型评审应如何分工？">4.5.7.3 面试问题：自动指标、人类评测和多模态大模型评审应如何分工？</h2>

**难度评分：⭐⭐⭐⭐⭐ (5/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

三者提供的是不同证据。自动指标适合高频回归，人类评测用于表达目标用户或专家的判断，多模态大模型评审负责扩大检查规模和生成结构化诊断。任何一类都不能自动等同于最终结论。

**自动指标适合稳定回归。** 它们成本低、易重复，适合每个 checkpoint 或代码变更后的固定集检查。代价是只测到预先定义的代理变量，因此更适合发现“哪项可能变了”，不适合独立决定整体体验是否提升。

**人类评测提供任务相关的偏好证据。** 盲测和成对比较通常比无锚点的绝对总分更容易控制尺度，但结果仍取决于人群、标注说明、样本覆盖和问题难度。需要随机化展示顺序，记录有效样本数、标注者一致性和置信区间；审美偏好可由目标用户判断，物理、安全或专业内容则可能需要专家。

**MLLM judge 用于规模化筛查和解释。** 它适合按评分规则（rubric）检查对象、属性、动作和关系，也可以生成失败标签。其判断会受到模型版本、视频采样方式、提示词、候选顺序和自身感知能力影响。已有研究发现，多模态 judge 在成对比较、绝对打分和批量排序上的可靠性并不相同，因此不能把一个维度上的相关性外推到所有任务。

落地时先建立带多人标注的校准集，固定 judge 版本、prompt、视频采样和候选顺序策略；分别计算各能力维度上的一致率或相关性，再决定使用、降权或停用。模型或 judge 升级、线上分布变化后都要重新校准。关键安全问题和 judge 明显不擅长的维度，应保留规则、专用检测器或人工复核。

> **面试速答**：自动指标负责低成本高频回归，人评提供目标用户或专家的偏好证据，MLLM judge 扩大覆盖并生成失败解释。人评本身也受样本和标注规范影响，MLLM judge 更需要按维度与人工校准。上线时固定评审协议，报告一致性与不确定性，高风险能力保留专用检查和人工复核。

参考资料：[MLLM-as-a-Judge](https://arxiv.org/abs/2402.04788)、[VBench](https://arxiv.org/abs/2311.17982)、[EvalCrafter](https://arxiv.org/abs/2310.11440)

<h2 id="4.5.7.4_面试问题：模型离线分数提升但用户体验没有变好，应如何排查？">4.5.7.4 面试问题：模型离线分数提升但用户体验没有变好，应如何排查？</h2>

**难度评分：⭐⭐⭐⭐⭐ (5/5)  |  考察频率：⭐⭐⭐⭐ (4/5)**

这种现象通常来自五类错配：离线提升没有超过测量噪声，离线与线上生成协议不一致，评测集与线上请求分布不同，代理指标奖励了错误行为，或者视频质量的收益被延迟、失败率和交互成本抵消。排查顺序要先保证比较成立，再讨论用户偏好。

1. **先确认提升是否真实。** 检查重复运行、seed 方差、样本量和置信区间。提升小于评测波动时，暂时不能推出模型能力已经改变。
2. **对齐生成协议。** 核对 checkpoint、EMA、prompt 重写、采样器、步数、CFG、seed 策略、分辨率、后处理和安全过滤。任一项不同，都可能让问题落在推理配置而非模型权重。
3. **重做业务分桶。** 比较离线与线上在任务类型、prompt 长度、主体数、运动强度、参考条件、时长和分辨率上的分布。总分上升但高频业务桶没有改善，用户无感是合理结果。
4. **检查指标奖励了什么。** 画质提高伴随运动减弱、时序分数提高伴随输出趋于静态、文本相似度提高但关系仍错误，都说明代理指标与业务目标不一致。需要回看样本和失败标签；继续调整总分权重无法解释问题。
5. **补齐端到端体验。** 将排队、生成时长、失败与重试、可控性、编辑成功率和单位成本纳入同一版本比较。最后对争议场景做盲测或线上 A/B，区分“质量确有提升但用户不重视”与“离线评估本身失真”。

**难度评分：⭐⭐⭐⭐⭐ (5/5)  |  考察频率：⭐⭐⭐⭐⭐ (5/5)**

持续验证需要将明确的能力要求用于训练检查点筛选、候选版本比较、发布检查和线上反馈分析，并保存对应的评测协议与数据版本。整体流程如图5-6所示。

**评测协议必须版本化。** prompt、参考条件、seed、生成参数、指标实现、judge 版本和人评规则都要随结果保存。否则分数变化可能来自评测链路升级，无法归因到模型。

**不同数据集承担不同职责。** 固定回归集用于长期比较，版本应尽量稳定；挑战集收集已知短板，随失败模式扩充；线上代表集按真实流量定期刷新，并完成隐私和安全处理。测试样本及其近重复内容一旦用于训练或反复调参，就不能继续作为独立测试证据。应记录受影响的样本和结果范围，使用未参与训练及开发调参的独立留出数据（holdout）重新验证，不能只删除相关样本后沿用旧分数。

**评估强度随发布阶段提高。** checkpoint 阶段运行便宜、稳定的自动回归；候选版本增加完整分维评测、人评和经过校准的 MLLM judge；发布前再检查安全、延迟、失败率和成本；小范围上线阶段按场景检查质量、严重错误和服务表现，并保留快速回滚能力。

**失败结果要能指向动作。** 每条严重失败至少包含任务类型、能力维度、输入规格、模型与推理版本、失败标签和复现信息，再归因到数据、条件解析、时空建模、采样解码或服务配置。修复后先回到对应挑战集验证，再检查固定回归集，防止局部问题改善后引入新的能力退化。

**发布条件要区分必须满足的要求与可权衡的指标。** 安全要求、核心场景的质量底线和严重一致性问题应设为必须通过的检查；一般画质、吞吐和成本可以按业务权重比较，但必须保留分项结果，不能只留一个总分。

> **面试速答**：先版本化 prompt、seed、生成配置、指标和评审协议，再用固定回归集守底线、挑战集跟踪短板、线上代表集对齐真实流量。checkpoint、候选版本、发布和灰度阶段逐步提高评估强度。测试样本用于训练或反复调参后，应记录受影响范围，并用独立留出数据重新验证。修复要先检查对应失败，再运行固定集检查其他能力，发布时保留明确条件与回滚能力。

参考资料：[The ML Test Score](https://research.google/pubs/the-ml-test-score-a-rubric-for-ml-production-readiness-and-technical-debt-reduction/)、[Hidden Technical Debt in Machine Learning Systems](https://papers.nips.cc/paper/5656-hidden-technical-debt-in-machine-learning-systems)、[VBench](https://arxiv.org/abs/2311.17982)
